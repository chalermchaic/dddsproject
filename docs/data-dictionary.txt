================================================================================
พจนานุกรมข้อมูล (Data Dictionary)
โครงการ: ระบบบริหารจัดการความสัมพันธ์ลูกค้า (CRM DFD System)
================================================================================

--------------------------------------------------------------------------------
ส่วนที่ 1: พจนานุกรมข้อมูลตารางหลักและคลังข้อมูล (Master Data & Data Stores D1–D5)
--------------------------------------------------------------------------------

ข้อมูลหลัก: Master Data: ข้อมูลพนักงานและผู้ใช้งาน (EMPLOYEE)
คำอธิบาย: ใช้เก็บทะเบียนพนักงาน สังกัดฝ่าย ตำแหน่งงาน และสิทธิ์การเข้าใช้งานระบบ เชื่อมโยงกับกิจกรรมการตลาด การติดตามขาย การออกบิล และงานบริการหลังการขาย
โครงสร้างตารางข้อมูล (Schema Definition):
  - Employee_ID (PK)     : VARCHAR(10)  -- รหัสพนักงาน (ขึ้นต้นด้วย EMP เช่น EMP001)
  - Employee_Name       : VARCHAR(100) -- ชื่อ-นามสกุลพนักงาน
  - Position            : VARCHAR(50)  -- ตำแหน่งงาน (เช่น 'พนักงานขาย', 'ช่างเทคนิค', 'นักการตลาด')
  - Department          : VARCHAR(50)  -- สังกัดฝ่าย ('ฝ่ายการตลาด', 'ฝ่ายขาย', 'ฝ่ายบริการลูกค้า')
  - Username            : VARCHAR(50)  -- ชื่อบัญชีเข้าใช้งาน (Unique)
  - Role                : VARCHAR(20)  -- สิทธิ์การใช้งาน ('admin', 'marketing', 'sales', 'support')

------------------------------------

คลังข้อมูล: D1: ข้อมูลผู้สนใจ (Leads Database)
คำอธิบาย: ใช้เก็บประวัติการลงทะเบียน รายละเอียดการติดต่อ และประวัติการติดตามเสนอขายของกลุ่มเป้าหมาย (Leads) ก่อนที่จะเปลี่ยนมาเป็นลูกค้าจริง (ประกอบด้วยตาราง LEAD และ LEAD_ACTIVITY)
โครงสร้างตารางข้อมูล (Schema Definition):
  [1] ตารางผู้สนใจหลัก (LEAD)
    - Lead_ID (PK)         : VARCHAR(10)  -- รหัสผู้สนใจ (ขึ้นต้นด้วย L เช่น L000000001)
    - Full_Name           : VARCHAR(100) -- ชื่อ-นามสกุล
    - Telephone           : VARCHAR(20)  -- เบอร์โทรศัพท์สำหรับติดต่อ
    - Email               : VARCHAR(100) -- อีเมลของผู้สนใจ
    - Source_Channel      : VARCHAR(50)  -- แหล่งที่มา (เช่น Facebook, Line, Google, Direct)
    - Campaign_ID (FK)     : VARCHAR(10)  -- รหัสแคมเปญโปรโมชันที่ผู้สนใจตอบสนอง (โยงกับ D5)
    - Followup_Status     : VARCHAR(20)  -- สถานะการติดตาม ('รอการติดต่อ', 'อยู่ระหว่างเสนอขาย', 'ปิดการขายสำเร็จ', 'ไม่สนใจ')
    - Created_At          : TIMESTAMP    -- วันเวลาที่ลงทะเบียนบันทึกผู้สนใจ

  [2] ตารางบันทึกกิจกรรมการติดตาม (LEAD_ACTIVITY)
    - Activity_ID (PK)     : VARCHAR(10)  -- รหัสบันทึกกิจกรรม (ขึ้นต้นด้วย A เช่น A000000001)
    - Lead_ID (FK)         : VARCHAR(10)  -- รหัสผู้สนใจที่ติดต่อ (โยงกับ LEAD)
    - Activity_Type        : VARCHAR(50)  -- ช่องทางการติดต่อ ('โทรศัพท์', 'อีเมล', 'ส่งไลน์', 'นัดพบ', 'ส่งโปรโมชัน')
    - Activity_Date        : DATETIME     -- วันและเวลาที่ติดต่อประสานงาน
    - Employee_ID (FK)     : VARCHAR(10)  -- รหัสพนักงานขายผู้รับผิดชอบการติดต่อ (โยงกับ EMPLOYEE)
    - Notes                : TEXT         -- บันทึกสรุปผลการพูดคุยเจรจา
    - Next_Action_Date     : DATE         -- วันที่นัดหมายติดต่อรอบถัดไป

------------------------------------

คลังข้อมูล: D2: ข้อมูลการขาย (Sales & Transaction Database)
คำอธิบาย: ใช้เก็บรายละเอียดใบเสนอราคา ข้อมูลคำสั่งซื้อ รายการสั่งซื้อของและสถานะชำระเงินในฝั่งยอดขาย (ประกอบด้วยตาราง SALE, SALE_DETAIL และ PRODUCT)
โครงสร้างตารางข้อมูล (Schema Definition):
  [1] ตารางหัวบิลการขาย (SALE)
    - Sale_ID (PK)         : VARCHAR(10)  -- รหัสการขาย (ขึ้นต้นด้วย S เช่น S000000001)
    - Lead_ID (FK)         : VARCHAR(10)  -- รหัสผู้สนใจที่เข้ากระบวนการสั่งซื้อ (โยงกับ D1)
    - Employee_ID (FK)     : VARCHAR(10)  -- รหัสพนักงานขายผู้รับผิดชอบการขาย (โยงกับ EMPLOYEE)
    - Quotation_No         : VARCHAR(20)  -- หมายเลขใบเสนอราคา
    - Quotation_Date       : DATE         -- วันที่ออกเอกสารใบเสนอราคา
    - Total_Amount        : DECIMAL(10,2)-- ราคาสุทธิรวมของธุรกรรมเสนอขาย
    - Sale_Status         : VARCHAR(20)  -- สถานะยอดขาย ('ออกใบเสนอราคาแล้ว', 'รอตรวจสอบคำสั่งซื้อ', 'รอการตรวจสอบชำระเงิน', 'ปิดการขายสำเร็จ')
    - Order_Confirmed_At  : TIMESTAMP    -- วันเวลาที่ผู้สนใจยืนยันคำสั่งซื้อ (Process 3.1)
    - Payment_Slip        : VARCHAR(100) -- ชื่อไฟล์หลักฐานสลิปโอนเงิน (Process 3.2 เก็บใน uploads/)
    - Invoice_No           : VARCHAR(20)  -- เลขที่ใบกำกับหนี้ / เลขที่ชำระเงิน
    - Payment_Ref         : VARCHAR(100) -- รหัสหลักฐานการโอนเงิน/อ้างอิงชำระเงิน
    - Confirmed_At        : TIMESTAMP    -- วันเวลาที่ยืนยันการรับเงินโอน

  [2] ตารางรายการสินค้าในบิล (SALE_DETAIL)
    - Sale_ID (PK, FK)     : VARCHAR(10)  -- รหัสการขาย (โยงกับ SALE)
    - Product_ID (PK, FK)  : VARCHAR(10)  -- รหัสสินค้า (โยงกับ PRODUCT)
    - Quantity             : INT          -- จำนวนสินค้าที่สั่งซื้อ
    - Unit_Price           : DECIMAL(10,2)-- ราคาต่อหน่วยที่ขายจริง
    - Subtotal             : DECIMAL(10,2)-- ราคารวมของรายการ (Quantity * Unit_Price)

  [3] ตารางข้อมูลสินค้า (PRODUCT - Master Data)
    - Product_ID (PK)      : VARCHAR(10)  -- รหัสสินค้า (ขึ้นต้นด้วย P เช่น P000000001)
    - Product_Name         : VARCHAR(150) -- ชื่อสินค้า/บริการ
    - Product_Category     : VARCHAR(50)  -- หมวดหมู่สินค้า
    - Unit_Price           : DECIMAL(10,2)-- ราคาขายมาตรฐานต่อหน่วย
    - Description          : TEXT         -- รายละเอียดสินค้า

------------------------------------

คลังข้อมูล: D3: ข้อมูลลูกค้า (Customer Profile Database)
คำอธิบาย: ใช้เก็บประวัติข้อมูลโปรไฟล์ของลูกค้าที่เป็นทางการ (หลังผ่านการชำระเงินปิดการขายแล้ว) เพื่อดูแลความสัมพันธ์และงานบริการ
โครงสร้างตารางข้อมูล (Schema Definition):
  - Customer_ID (PK)     : VARCHAR(10)  -- รหัสลูกค้าที่เป็นทางการ (ขึ้นต้นด้วย C เช่น C000000001)
  - Lead_ID (FK)         : VARCHAR(10)  -- รหัสผู้สนใจเดิม เพื่อเชื่อมโยงประวัติการคัดกรอง (โยงกับ D1)
  - Company_Name        : VARCHAR(150) -- ชื่อบริษัท (ถ้ามี)
  - Tax_ID              : VARCHAR(20)  -- เลขประจำตัวผู้เสียภาษี
  - Billing_Address     : TEXT         -- ที่อยู่จัดส่งเอกสารใบกำกับภาษี/ใบเสร็จ
  - Shipping_Address    : TEXT         -- ที่อยู่จัดส่งสินค้า
  - Customer_Type       : VARCHAR(20)  -- ประเภทลูกค้า (เช่น 'ทั่วไป', 'องค์กร / VIP')
  - Membership_Date     : DATE         -- วันที่ยกระดับขึ้นทะเบียนเป็นลูกค้าทางการ

------------------------------------

คลังข้อมูล: D4: ข้อมูลปัญหาและการแก้ไข (Service Ticket & Ticket Logs Database)
คำอธิบาย: ใช้เก็บประวัติรายการขอความช่วยเหลือหรือปัญหาการใช้งานสินค้าของลูกค้า (Service Ticket) และขั้นตอนวิธีดำเนินการแก้ไขปัญหาของฝ่ายบริการ (ประกอบด้วยตาราง TICKET และ TICKET_MESSAGE)
โครงสร้างตารางข้อมูล (Schema Definition):
  [1] ตารางหัวข้อปัญหาบริการ (TICKET)
    - Ticket_ID (PK)       : VARCHAR(10)  -- รหัสแจ้งซ่อม/บริการหลังการขาย (ขึ้นต้นด้วย T เช่น T000000001)
    - Customer_ID (FK)     : VARCHAR(10)  -- รหัสลูกค้าผู้แจ้งเคส (โยงกับ D3)
    - Product_ID (FK)      : VARCHAR(10)  -- รหัสสินค้าที่มีปัญหา (โยงกับ D2/PRODUCT)
    - Problem_Category    : VARCHAR(50)  -- หมวดหมู่ปัญหา (เช่น 'ระบบขัดข้อง', 'สินค้าชำรุด', 'ขอข้อมูลเพิ่ม')
    - Problem_Title       : VARCHAR(150) -- หัวข้อเรื่องที่แจ้งปัญหา
    - Ticket_Status       : VARCHAR(20)  -- สถานะการแก้ไข ('รอดำเนินการ', 'กำลังแก้ไข', 'ปิดเคสสำเร็จ')
    - Employee_ID (FK)     : VARCHAR(10)  -- รหัสพนักงาน/ช่างเทคนิคที่ได้รับมอบหมาย (โยงกับ EMPLOYEE)
    - Created_At          : TIMESTAMP    -- วันเวลาเริ่มต้นแจ้งปัญหา
    - Closed_At           : DATETIME     -- วันที่ปิดเคสการบริการหลังการขายสำเร็จ
    - Service_Rating      : INT          -- คะแนนประเมินความพึงพอใจการบริการ (1–5 ดาว, Process 4.3)
    - Service_Feedback    : TEXT         -- ข้อคิดเห็นหรือข้อเสนอแนะเพิ่มเติมจากลูกค้า

  [2] ตารางประวัติการถาม-ตอบและบันทึกการแก้ไขปัญหา (TICKET_MESSAGE)
    - Message_ID (PK)     : VARCHAR(10)  -- รหัสข้อความ (ขึ้นต้นด้วย MSG เช่น MSG0000001)
    - Ticket_ID (FK)       : VARCHAR(10)  -- รหัสเคสปัญหาที่อ้างอิง (โยงกับ TICKET)
    - Sender_Type         : VARCHAR(20)  -- ผู้ส่ง (เช่น 'Customer', 'Support_Staff')
    - Sender_Name         : VARCHAR(100) -- ชื่อผู้ส่งข้อความ
    - Message_Text        : TEXT         -- ข้อความถาม-ตอบ หรือบันทึกขั้นตอนและผลการแก้ไขปัญหา
    - Sent_At             : TIMESTAMP    -- วันเวลาที่ส่งข้อความ

------------------------------------

คลังข้อมูล: D5: ข้อมูลแคมเปญและโปรโมชัน (Marketing Campaign Database)
คำอธิบาย: เก็บประวัติแผนการตลาด กิจกรรมแคมเปญ และข้อมูลโปรโมชัน (เช่น ส่วนลด, แถมสินค้า) เพื่อดึงไปเสนอขายหรือออกรายงานวิเคราะห์
โครงสร้างตารางข้อมูล (Schema Definition):
  - Campaign_ID (PK)     : VARCHAR(10)  -- รหัสแผนแคมเปญการตลาด (ขึ้นต้นด้วย M เช่น M000000001)
  - Campaign_Name       : VARCHAR(150) -- ชื่อโครงการแคมเปญ
  - Promotion_Details   : TEXT         -- รายละเอียดสิทธิพิเศษ/โปรโมชันของโครงการ
  - Discount_Rate       : DECIMAL(5,2) -- อัตราส่วนลดคิดเป็นร้อยละ (0-100)
  - Budget_Cost         : DECIMAL(10,2)-- งบประมาณที่ใช้ลงทุนจัดแคมเปญ
  - Start_Date          : DATE         -- วันที่เริ่มโปรโมชัน
  - End_Date            : DATE         -- วันที่สิ้นสุดโปรโมชัน
  - Campaign_Status     : VARCHAR(20)  -- สถานะแคมเปญ ('เปิดใช้งานอยู่', 'หมดอายุ')
  - Employee_ID (FK)     : VARCHAR(10)  -- รหัสพนักงานการตลาดผู้สร้างแคมเปญ (โยงกับ EMPLOYEE)


--------------------------------------------------------------------------------
ส่วนที่ 2: พจนานุกรมการไหลของข้อมูล (Data Flow Dictionary - Major Flows)
--------------------------------------------------------------------------------

ชื่อเส้นข้อมูล: ข้อมูลการติดต่อ (Contact Info)
คำอธิบาย: รายละเอียดการลงทะเบียนครั้งแรกของผู้สนใจผ่านหน้าเว็บ หรืออีเมลติดต่อ
โครงสร้างรายละเอียด (Composite Fields):
  = [ Full_Name ] +
    [ Telephone ] +
    [ Email ] +
    [ Source_Channel ] +
    { Product_Interest }

------------------------------------

ชื่อเส้นข้อมูล: ใบเสนอราคา (Quotation Document)
คำอธิบาย: เอกสารระบุราคาสินค้าตามเงื่อนไขโปรโมชันที่ส่งให้ลูกค้าตัดสินใจซื้อ
โครงสร้างรายละเอียด (Composite Fields):
  = [ Quotation_No ] +
    [ Lead_Name ] +
    [ Quotation_Date ] +
    { Item_No + Product_Name + Unit_Price + Quantity + Subtotal } +
    [ Discount_Amount ] +
    [ Net_Total ]

------------------------------------

ชื่อเส้นข้อมูล: คำสั่งซื้อ (Sales Order)
คำอธิบาย: การยืนยันความจำนงในการสั่งซื้อที่ส่งจากลูกค้าหลังพอใจในใบเสนอราคา
โครงสร้างรายละเอียด (Composite Fields):
  = [ Quotation_Ref_No ] +
    [ Order_Date ] +
    [ Shipping_Details ] +
    [ Billing_Details ] +
    [ Net_Total ]

------------------------------------

ชื่อเส้นข้อมูล: หลักฐานชำระเงิน (Payment Receipt Proof)
คำอธิบาย: หลักฐานการโอนเงินชำระเงินมัดจำหรือชำระเต็มจำนวนเพื่อปิดงานเสนอขาย
โครงสร้างรายละเอียด (Composite Fields):
  = [ Bank_Slip_Image ] +
    [ Transfer_DateTime ] +
    [ Bank_Account_No ] +
    [ Paid_Amount ] +
    [ Order_Ref_No ]

------------------------------------

ชื่อเส้นข้อมูล: ข้อมูลแจ้งปัญหา (Support Ticket Complaint)
คำอธิบาย: บันทึกร้องเรียนความพึงพอใจหรืออธิบายอาการเสีย/การบริการที่บกพร่อง
โครงสร้างรายละเอียด (Composite Fields):
  = [ Customer_ID ] +
    [ Problem_Category ] +
    [ Detailed_Description ] +
    { Attach_Photo }

------------------------------------

ชื่อเส้นข้อมูล: ข้อมูลปัญหาและการแก้ไข (Service Ticket History)
คำอธิบาย: ประวัติการแจ้งซ่อมแซมและการเข้าดำเนินการช่วยเหลือของช่างเทคนิคที่จัดเก็บถาวร
โครงสร้างรายละเอียด (Composite Fields):
  = [ Ticket_ID ] +
    [ Customer_ID ] +
    [ Problem_Description ] +
    [ Resolution_Details ] +
    [ Ticket_Status ]

ส่วนที่ 3: ตารางแหล่งข้อมูลภายนอก (External Entity Definition)
--------------------------------------------------------------------------------

1. ฝ่ายการตลาด (Marketing Dept.)
   - คำอธิบาย: ผู้ดำเนินการวิเคราะห์ตลาด วางโครงการโปรโมชัน (แคมเปญ) และป้อนข้อมูล Leads รายชื่อผู้สนใจจากช่องทางออฟไลน์/ออนไลน์เข้าสู่ระบบ
   - การปฏิสัมพันธ์: ส่งข้อมูลแคมเปญ, ดึงข้อมูลประสิทธิผลการตลาดเพื่อออกรายงานประสิทธิภาพแคมเปญ

2. ผู้สนใจ (Lead / Prospect)
   - คำอธิบาย: บุคคลภายนอกที่แสดงความต้องการเข้าหาบริการหรือสอบถามราคาเป็นครั้งแรก (ยังไม่มีรายการขายและยังไม่เคยจ่ายเงิน)
   - การปฏิสัมพันธ์: ลงทะเบียนส่งข้อมูลการติดต่อ เพื่อรอเจ้าหน้าที่เสนอเงื่อนไขรายละเอียดโปรโมชันกลับไปให้พิจารณา

3. ฝ่ายขาย (Sales Dept.)
   - คำอธิบาย: พนักงานขายและทีมเจรจาธุรกิจ ทำหน้าที่นำเสนอขาย แนะนำคุณสมบัติ อัปเดตกิจกรรมการติดต่อและเสนอราคา
   - การปฏิสัมพันธ์: ได้รับ To-Do List รายชื่อผู้สนใจที่ต้องโทรหาประจำวัน, บันทึกสถานะกิจกรรมและสถานะการปิดเคส, ได้รับรายงานสรุปยอดขาย

4. ลูกค้า (Customer)
   - คำอธิบาย: ผู้ที่ผ่านการซื้อขายกับระบบอย่างเป็นทางการ ได้รับการออกหมายเลขลูกค้า (Customer_ID) และทะเบียนข้อมูลในระบบถาวร
   - การปฏิสัมพันธ์: ส่งคำสั่งซื้อและหลักฐานชำระเงิน, ได้รับเอกสารใบเสร็จรับเงิน, ส่งใบแจ้งปัญหาหลังการขายเพื่อขอรับคำอธิบาย/สถานะการซ่อมบำรุง

5. ฝ่ายบริการลูกค้า (Customer Support)
   - คำอธิบาย: พนักงาน Call Center หรือเจ้าหน้าที่ซ่อมบำรุงเทคนิคหลังการขาย ทำหน้าที่ประสานงานแก้ไขเคสแจ้งเคลมหรือร้องเรียน
   - การปฏิสัมพันธ์: ได้รับใบสรุปรายการปัญหาค้างดำเนินการ, ส่งบันทึกผลงานแก้ไขอัปเดตเข้าระบบ
